# 搞健康 V4.05

独立 macOS 应用，包含本模块完整业务、游戏场景和 WidgetKit 小组件。运行不依赖搞七廿三或其他六个应用；联动功能需要同时安装相关应用。

## 下载与安装

从 [Releases](https://github.com/UCASerYff/GaoJianKang/releases/latest) 下载 `GaoJianKang-4.05.zip` 和同名 `.sha256` 文件。仓库保存源码，安装包作为 Release 附件单独发布。

1. 支持 macOS 14 或更高版本、Apple Silicon；暂未提供 Intel 版本。
2. 解压 ZIP，将 `搞健康.app` 拖入“应用程序”文件夹。
3. 如果 macOS 拦截打开，请先确认软件来源，再进入“系统设置 → 隐私与安全性”，允许该应用打开。发行包使用 Apple Development 签名，未做 Apple 公证。
4. 安装后运行一次，再从系统小组件列表添加本应用的小组件。整合版的小组件需要重新添加。

下载后可在文件所在目录运行 `shasum -a 256 -c GaoJianKang-4.05.zip.sha256` 核验安装包。

## 功能

- 记录饮食来源与饱食百分比、运动、心情等健康活动，查看历史和趋势。
- 三维岛屿：设施建设、升级、扩建与布局模式。
- 「睡眠记录」以小时、分钟为主要输入，与搞节奏一致。选择哪晚（就寝日期），按次日早上 7:00 换算起床时间；在任一侧录入即可自动共享。
- 喝水、饮食、运动、体重、睡眠及快速事项均提供明确的补记入口。默认昨天，可改为更早日期或今天早些时候；编辑已有记录保留原时间。普通记录按健康设置的时区归档，睡眠日期换算与搞节奏一致，采用系统时区。
- 两边运行时收到通知即同步，并每 15 秒补查；搞节奏关闭时，下次打开同步历史与小组件。同步仅限同一台 Mac，不经过云端。
- 睡眠按原 ID 导入，保留历史、牧场进度及领奖标记；同步删除带删除标记，旧副本不会复活。
- 睡眠每小时恢复 3 点岛屿活力，每日最多 24 点；最近 36 小时结束且时长 30 分钟至 24 小时的记录可领一次。游戏暂停/关闭时不领奖，记录仍保存。

- 从菜单或 ⌘, 打开设置，提供外观、模块设置、备份与恢复。
- 提供本应用对应的桌面/通知中心小组件。

## 用户数据、附件与隐私

源码及安装包不包含个人记录、账户配置、账单、健康数据、私人附件、API 密钥、浏览器会话或用户备份。新电脑首次打开时创建自己的资料库；GitHub 下载不能恢复个人数据。

- 业务数据目录：`~/Library/Application Support/GaoSeries/Health/`。
- 数据库或小组件镜像：`~/Library/Group Containers/5G96498KGJ.com.gaoseries.GaoJianKang/`。
- 设置保存在本应用的 UserDefaults 域；凭据由 macOS 钥匙串管理，不导出到普通备份文件。
- 公开安装包会删除本机编译路径、源文件索引及扩展属性，再重新签名。签名证书的公开身份信息随软件发布，签名私钥不在仓库或安装包中。

真实业务历史完整保留。界面采用分页或归档减轻加载；游戏事件最多保留 300 条、抽取记录最多 200 条、词元账户显示采样最多 300 条，累计收益、余额、保底计数、库存与游戏进度独立保存。

共享睡眠保存在健康 App Group 的 `SharedSleep/sleep-records.sqlite`。两边共享同一份记录，其他资料仍保存在各自原路径。搞健康的完整资料 ZIP 包含共享睡眠；模块内 `.healthbackup` 仅备份健康与岛屿，完整迁移请使用 ZIP。

## 数据迁移与恢复

V4.0 从整合版拆分时保留业务历史、余额、库存、游戏进度、设置和全部附件。独立应用继续使用各自的数据目录，升级或替换应用程序不会删除这些数据。

在设置的数据页导出“完整资料 ZIP 备份”。恢复备份可迁移本应用的资料、App Group 镜像、设置以及已管理的 PDF、Word、照片等附件。备份使用逐文件 SHA-256 校验与 SQLite WAL 一致快照，恢复前保存安全副本；待下次启动应用时应用恢复。备份必须来自同一应用，不能将另外一个模块的备份直接导入。钥匙串凭据需在新电脑重新配置。

迁移临时副本不属于程序运行依赖，确认数据与附件完整后可自行清理。个人备份应单独保管，不应放进源码目录或上传公开仓库。

## 从源码构建

需要完整 Xcode、Python 3 和 Apple Silicon Mac。默认脚本使用项目配置的开发签名身份；自行构建需使用自己的 Apple Development 证书，并相应调整签名团队、App Group 权限及小组件工程配置。

```sh
./scripts/build.sh
./scripts/package.sh
./scripts/install.sh
```

通过环境变量 `GAO_SIGNING_IDENTITY` 可指定签名证书。修改团队后也需调整 `scripts/install.sh` 中的团队检查。`dist/` 存放本地发行 ZIP 和校验文件，不提交到 Git；上传到 GitHub Releases。

- `Sources/`、`Shared/`（如有）与 `Module.swift`：业务和游戏逻辑。
- `GameWorld/` 与 `Resources/`：场景、模型、贴图和其他资源。
- `Host/`：独立入口、设置、完整备份和联动服务。
- `Widgets/`：小组件；`Tests/`：回归验证。

## 版本更新

版本以 `Info.plist` 为准。后续功能改动仅更新受影响的应用，默认版本 +0.01、构建号 +1。先核验用户资料，再安装新程序并检查记录、附件和游戏进度，成功后清理旧程序、安装包与中间构建。程序资源与用户资料须分别处理，不能用清理构建目录的方式删除用户数据。

第三方组件和资源保留各自许可，详情见 `Resources/` 中的许可、来源说明与补丁记录。

## V4.03 小组件资料一致性

主程序与两类小组件统一使用原 App Group 的 `Health/health.sqlite`。小组件读取使用只读现有库，按钮使用可写现有库；缺库、损坏或未知版本不会初始化空白资料。多表读取使用同一 SQLite 快照，内容编辑不再只依赖时间戳判断是否落库。

成功提交后统一定向刷新本应用的日常与小岛、快速事项两种 kind，并通知正在运行的主程序。每次实际按钮执行使用独立操作 ID；相同事务请求仍保留重放防重。主程序在唤醒、跨日、时钟和时区变化时重读，常驻期间以低频只读检查兜底，不用高频 WidgetKit reload 循环。

组件从原业务库生成带校验的原子缓存，失败显示“上次有效资料”或“暂不可读取”，不会伪造零值；发布失败保留重试状态。资料更新、最近记录、缓存生成和成功读取时间分开记录，未来 Timeline 仅按原规则推算小岛和统计日期，不改变真实记录的发生时间。日常与小岛预排未来 48 小时的半小时和配置时区午夜条目，事项月历仅预排当前及午夜条目，系统实际刷新时间仍由 WidgetKit 决定。

共享睡眠协议和搞节奏源码不变。组件需要时只读原共享睡眠库，在健康库中按原规则领取有效睡眠奖励，不重新导入、改写对方资料或重复领奖。

`./scripts/test_widget_data.sh` 是临时目录中的生产数据库/缓存/时间线定向测试，不启动 App、浏览器、模拟器或桌面窗口。默认不进行冒烟测试。真实桌面最终显示与延迟、不同尺寸和多个实例、重加、重启、睡醒及真实午夜仍需用户手动验收；不能仅凭 reload 调用、编译或隔离测试宣布实际桌面刷新问题已完全解决。诊断记录位于健康资料目录的 `WidgetDiagnostics-v1.json`，只保留最近 32 条摘要，含时间、版本摘要和数量，不上传到仓库。

WidgetKit 的请求与展示由系统调度，开发者不能用计划 entry 日期证明最终展示时刻，参见 [Apple：Keeping a widget up to date](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)。

## V4.04 恢复与安装安全

完整恢复在替换现有资料之前验证备份中的真实健康数据库、支持的存储/业务版本及完整记录，缺失或不可读的主库不能被当成空白资料恢复。恢复前保留原偏好域，包括明确不存在的状态；失败或可恢复的中断同时回滚资料与偏好，原钥匙串保持不变。

安装优先使用校验过的发行归档，同时核对主程序、框架、小组件的身份及版本/构建。暂存和回滚全过程使用 `.noindex` 容器，回滚归档、摘要和恢复收据保留。安装脚本成功不能替代实际用户会话的 Spotlight、LaunchServices 与唯一正式入口核验。

原第 07 项的实际桌面、真实按钮往返、全尺寸多实例、生命周期与时间边界验收仍按证据逐项记录。已完成的隔离测试不改写为真实桌面通过；外接设备相关项标为“不做（用户取消）”，不计为通过。

## V4.05 事项中号布局

实际中号组件出现标题和底部资料时间被裁切。中号将月汇总并入月份标题，缩小右栏间距，并使用紧凑按钮，保留三个快捷入口、全部事项链接及资料状态信息。统计与共享睡眠继续使用原数据路径和协议。
